## 3. 指令、坐标与高度权限

生产新路径需同时显式选择 `visual_navigation_enabled=true` 与 `px4_horizontal_enabled=true`；两者的默认值仍为 false。任务默认 `control_enabled=false`。仅启动任务/相机不会给它PX4发布权。

- 实际反馈：PX4融合的局部NED位置 m、速度 m/s、FRD→NED Hamilton `wxyz` 姿态。MTF‑02P继续先进入PX4融合。
- 任务内部：ENU/FLU。任务发出的世界垂向意图固定为0；相机目标相对测量不作为自机实际速度。
- 定点/航点：`/fc01/navigation/command`，可靠、volatile、keep-last 1。frame绑定完整PX4局部原点；Cruise只取XY与有效yaw。
- 跟踪：新增 `/fc01/vision/horizontal_command` / `HorizontalVelocityCommand`，同样keep-last 1。封套嵌入旧V2载荷，同时携带 `attitude_sample_stamp_ns` 与 `origin_id`。原V2字段和诊断端点保留。
- 完整三维FRD→NED旋转后只取XY。倾斜时世界水平速度在机体系内可以有z补偿，提前清body-z会扭曲水平结果。明确的纯body-Z请求（vx=vy=0）按零水平需求处理；这项策略例外已写入合同和测试。
- 封套中的 `wz` 是**期望NED航向速率** rad/s，下轴顺时针为正；区别于PX4实测机体系角速度。0保持已积分/提交航向，不将0理解为绝对朝北。
- 原生高度始终由本次 `h=z0-z`、PX4融合z/vz与原垂向环闭环，目标1.5m；新选择器拒绝不为1.5m的RC目标配置。航点z、视觉垂向速度和模拟高度参数均无垂向权限。

默认包络为水平速度0.5m/s、水平加速度幅值0.6m/s²、视觉倾角5°、偏航速率0.35rad/s、半径2m，同时继续满足原生总倾角/推力/总限高合同。加速度这里是幅值限制，不声称具有jerk或逐周期加速度变化率限制。

任务半径锚点是本轮首个有效平台位置；原生半径锚点是本轮首次合格到高水平控制周期的实际XY。两道门是保守交集，不能宣称使用同一个起飞点。航点还需现场确认与当前完整PX4原点相同。

## 4. 仲裁和故障动作

执行顺序保持：实际反馈有效 → 来源/重置连续 → 两通道连续性 → 来源唯一 → 单一意图 → 限幅 → 姿态计划 → 原发布边界。

1. 到高前所有水平意图只等待，原生高度环独占起飞。
2. 到高但尚无可靠任务输入时，捕获原生XY保持点并继续定高；没有相机不会自动触发下降。
3. 同周期跟踪与航点均有效时，只选当前跟踪，禁止叠加。
4. 航点 `valid=false` 是正常通道撤销。下一路跨周期到达时有限刹停，至多一个原生命令TTL（默认0.30秒）；等待超限走既有下降。
5. 跟踪已开始后，失锁/超时/invalid/缺匹配姿态/来源或参考重置撤销XY和偏航，走原生受保护下降；旧航点不得接管掩盖故障。
6. RC接管、Kill、DDS/RC失联、电池和PX4 failsafe仍由原生既有门优先处理。任务故障不靠目标重新出现自清，只能随当前原生进程真实新任务epoch重新准备。

简化垂向模型的normal结果：目标1.5m、超调0.139893m；从推力爬坡到稳定窗入口7.91222s，到HeightHold10.1814s；后续3.35906s观察窗内最大误差0.139893m、RMS0.132082m；最长心跳接收间隔0.0539543s，wire时间戳间隔0.05077s。这不是实飞定高精度、长期稳定时间或相机延时结论。

XY在该模型中固定，0漂移是输入设定，**没有水平动力学闭环稳定证明**。没有可用同期Position ULog作性能对照，也没有把合成图像解释为真实视觉性能。任务DDS收发和原生DDS控制路径分别验证，尚未同时运行真实相机→mission→原生→真实PX4的整机闭环。
